## Project: S.C.O.P.E.

- Description: A 4-role distributed assessment platform replacing third-party tools like HackerRank for institutional placement drives. Architected with Nginx least-conn load balancing, Redis async queuing, and Dockerized Judge0 execution nodes — validated at 0% failure rate across 40,000 requests at 200 concurrent connections, supporting 1,000+ concurrent users.
- Technologies: React, Node.js, PostgreSQL, Linux, Redis, Nginx, Docker, Judge0

### Overview

S.C.O.P.E. (Secure Competitive Online Platform for Examinations) is a full-stack exam platform built for the Training & Placement department at Thakur College of Engineering and Technology (TCET), Mumbai. It is a self-hosted, on-premise system that runs inside the college LAN. The platform supports 500+ concurrent students with role-based access for students, teachers, T&P faculty, and super administrators. It includes live code execution via Judge0 across 10 distributed nodes, MCQ testing with aptitude and technical sections, real-time exam monitoring via WebSockets, and anti-cheat enforcement via Safe Exam Browser (SEB). Built by Anuj Singh, Ganesh Singh, and Aniket Bhaskar.

### Timeline

March 2026 – April 2026

### Problem Statement

Third-party assessment tools could not be used because the college required a fully owned, self-hosted system that runs on a private LAN with zero external dependencies — no internet required and no data leaves the campus. ### Architecture

#### Architecture Style

Monolithic backend with modular routing, feature-based module organization. The repository is split into two top-level directories (SCOPE-Backend/ and SCOPE-Frontend/). The backend follows a layered structure within modules: routes → controller → service patterns, though most business logic resides in controllers.

Patterns:
- MVC-like (routes define endpoints, controllers handle logic, Prisma/Postgres as model layer)
- Feature-based modules (auth/, admin/, teacher/, student/, tnp/, compiler/)
- Repository pattern via Prisma ORM
- Middleware chain for auth + authorization
- Background polling for telemetry (cached in RAM)

#### Request Flow

```
Student Device (SEB)
  ↓ LAN Request
React Frontend (Vite :5173)
  ↓ fetch/Axios HTTP
Express Backend (:5000)
  ↓ auth.middleware.js (protect + restrictTo)
Controller (business logic)
  ↓ Prisma Client
PostgreSQL 16 Database
  ↓ Response flows back up
```

For code execution:
```
Student writes code in Monaco Editor
  ↓ POST /api/student/exam/:id/submit-code
Express Backend
  ↓ HTTP POST to Judge0 nodes (via Nginx load balancer)
Nginx (least_conn)
  ↓ Distributes to 1 of 10 nodes
Judge0 Node (:2358)
  ↓ Code compilation + execution
Response flows back with test results
  ↓ Prisma stores best-attempt submission
```

For real-time exam time sync:
```
T&P Admin updates exam time
  ↓ POST /api/tnp/test/:id/sync-time
Express updates DB + broadcasts via Socket.io
  ↓ io.to(examId).emit('exam_time_synced', ...)
All students in exam room receive update
```
