## Project: S.C.O.P.E. — Overview

S.C.O.P.E. (Secure Competitive Online Platform for Examinations) is a full-stack exam platform built for the Training & Placement department at Thakur College of Engineering and Technology (TCET), Mumbai. It is a self-hosted, on-premise system that runs inside the college LAN. The platform supports 1000+ concurrent students with role-based access for students, teachers, T&P faculty, and super administrators. It includes live code execution via Judge0 across 10 distributed nodes, MCQ testing with aptitude and technical sections, real-time exam monitoring via WebSockets, and anti-cheat enforcement via Safe Exam Browser (SEB). Built by Anuj Singh, Ganesh Singh, and Aniket Bhaskar.

- Project Name: S.C.O.P.E.
- Full Name: Secure Competitive Online Platform for Examinations
- Technologies: React, Node.js, PostgreSQL, Linux, Redis, Nginx, Docker, Judge0
- Category: Full-Stack Web Application, Distributed Assessment Platform
- Timeline: March 2026 – April 2026
- GitHub: https://github.com/Ganesh-AIML/SCOPE.git

### Problem Statement

Third-party assessment tools could not be used because the college required a fully owned, self-hosted system that runs on a private LAN with zero external dependencies — no internet required and no data leaves the campus. The platform needed to support placement exam workflows including MCQ testing (aptitude + technical), live coding evaluation, distributed code execution, and role-based invigilation workflows.

### Target Users

Students, teachers, T&P (Training & Placement) faculty, and super administrators at Thakur College of Engineering and Technology, Mumbai.

### User Roles

- **STUDENT**: Appears for exams (MCQ + coding), views past results and analysis dashboards, updates password
- **TEACHER**: Approves/rejects student registrations by department, views active students, bulk resets student passwords, bulk uploads students via CSV, views test credentials for invigilation, updates own password
- **TNP_ADMIN**: Creates and schedules tests, builds MCQ sections (manual or via Aiken file import), builds coding problems with test cases and boilerplates, monitors live exams with real-time telemetry, views analytics and student performance profiles, syncs exam time live via WebSockets, archives tests, performs ZIP-based bulk coding problem upload
- **SUPER_ADMIN**: Approves/rejects/suspends teachers and T&P admins, views all users, resets passwords for any user, performs bulk password resets for staff, views system health telemetry dashboard (node CPU/RAM, Nginx active connections, Redis queue length)

## Project: S.C.O.P.E. — Architecture & Workflow

This section describes the architecture and request flow of S.C.O.P.E. (Secure Competitive Online Platform for Examinations).

- Project Name: S.C.O.P.E.
- Technologies: React, Node.js, PostgreSQL, Linux, Redis, Nginx, Docker, Judge0

### Architecture Style

Monolithic backend with modular routing, feature-based module organization. The repository is split into two top-level directories (SCOPE-Backend/ and SCOPE-Frontend/). The backend follows a layered structure within modules: routes → controller → service patterns, though most business logic resides in controllers.

Patterns:
- MVC-like (routes define endpoints, controllers handle logic, Prisma/Postgres as model layer)
- Feature-based modules (auth/, admin/, teacher/, student/, tnp/, compiler/)
- Repository pattern via Prisma ORM
- Middleware chain for auth + authorization
- Background polling for telemetry (cached in RAM)

### Request Flow

```
Student Device (SEB)
  ↓ LAN Request
React Frontend (Vite :5173)
  ↓ fetch/Axios HTTP
Express Backend (:5000)
  ↓ auth.middleware.js (protect + restrictTo)
Controller (business logic)
  ↓ Prisma Client
PostgreSQL 16 Database
  ↓ Response flows back up
```

For code execution:
```
Student writes code in Monaco Editor
  ↓ POST /api/student/exam/:id/submit-code
Express Backend
  ↓ HTTP POST to Judge0 nodes (via Nginx load balancer)
Nginx (least_conn)
  ↓ Distributes to 1 of 10 nodes
Judge0 Node (:2358)
  ↓ Code compilation + execution
Response flows back with test results
  ↓ Prisma stores best-attempt submission
```

For real-time exam time sync:
```
T&P Admin updates exam time
  ↓ POST /api/tnp/test/:id/sync-time
Express updates DB + broadcasts via Socket.io
  ↓ io.to(examId).emit('exam_time_synced', ...)
All students in exam room receive update
```

### Database

- **Engine**: PostgreSQL 16
- **Tables**: 13 total (11 application tables + 2 migration tracking)
- **Key Entities**: users, student_profiles, staff_profiles, TnpTest, TnpSection, TnpQuestion, TnpCodingProblem, TnpTestCase, StudentResult, McqSubmission, CodingSubmission
- **Relationships**: User 1:1 StudentProfile / StaffProfile, User 1:N StudentResult, TnpTest 1:N TnpSection/TnpCodingProblem/StudentResult (cascade delete), TnpSection 1:N TnpQuestion (cascade delete), TnpCodingProblem 1:N TnpTestCase (cascade delete), StudentResult 1:N McqSubmission/CodingSubmission (cascade delete)

  ↓

### Architecture

Mobile App → Backend-as-a-Service (Firebase) → Serverless Functions → Third-party Services (Twilio)

Layered architecture:
- **Presentation Layer**: Flutter UI (pages, widgets)
- **Service Layer**: Flutter services (SOS handler, audio recorder, SMS service, Firebase services)
- **Backend Layer**: Firebase Cloud Functions running Express.js, Python Flask server
- **External Layer**: Twilio for voice/SMS, Google Maps for mapping, GNews for news

### Request Flow — SOS Activation

```
User taps SOS button (or secret code entered)
  → SOSPage opens with 10-second countdown
  → Timer expires → EmergencyHandler.sendEmergency()
  → SMSService.sendSOSMessage(): gets GPS location, launches SMS with Google Maps link
  → EmergencyService.captureEmergencyImages(): takes photos, uploads to Firebase Storage
  → AudioRecorder.startRecording(): records 10 seconds AAC audio, uploads to Firebase Storage
  → HTTP POST to Firebase Cloud Function /trigger endpoint
  → Cloud Function creates Twilio voice call to user's phone
  → User receives IVR: "Press 1 if safe, Press 0 if need help"
```

## Project: Exoplanet Classifier — Features & Architecture

This section describes the features and architecture of the Exoplanet Detection & Habitability Classifier.

- Project Name: Exoplanet Detection & Habitability Classifier
- Technologies: Python (Flask), XGBoost, Scikit-Learn, Plotly

### Core Features

- Exoplanet candidate classification using Random Forest model
- Binary classification: candidate (1) or non-candidate (0)
- Habitability classification using rule-based stellar and planetary parameter thresholds
- CSV file upload for custom data analysis
- Sample data analysis using pre-loaded Kepler dataset
- Results download as CSV

### Visualization Features

- Goldilocks Zone Plot (temperature vs. insolation flux with habitable zone overlay)
- Temperature-Insolation Habitability Heatmap (KDE-based probability density)
- Planetary Profile Radar Comparison (up to 5 candidates compared to Earth)
- Orbit Map (polar scatter plot based on orbital period, color-coded by habitability)
- Galactic Map with Habitability Zones (RA/Dec sky coordinates)
- Feature Pair Explorer (custom scatter plot of any two numeric features)

### AI/ML Pipeline

- **Model Type**: scikit-learn Pipeline (StandardScaler + RandomForestClassifier)
- **Inference**: Model loaded via pickle.load(), used with model.predict()
- **Feature Engineering**: luminosity_proxy, habitable_zone_proxy, size_ratio derived before prediction
- **Habitability Classification**: Rule-based (NOT from ML model) — stellar classification (F/G/K/M), planet radius 0.5–5.0 Earth radii, temperature 175–270 K, insolation flux 0.32–1.77 Earth flux
- **Libraries**: scikit-learn, xgboost, numpy, scipy

### Architecture

Monolithic Flask application. A single Flask app serves both frontend (rendered HTML template) and backend (REST API endpoints). The ML model is loaded at startup from a pickled file and used for on-demand predictions.

**Pipeline**: Data Ingestion → CSV Parsing → Feature Engineering → Model Prediction → Habitability Classification → JSON Response → Client-side Plotly Visualization
